# 档案馆 · 库房与卷宗调阅管理系统

档案馆日常台账：**库房与卷宗**、**案卷目录**、**到期鉴定台**、**调阅登记**、**库房温湿度**。

## 技术栈

Spring Boot 3.3（Java 17）+ MySQL 8.0 + Redis 7 + Vue 3 + Element Plus + Vite + nginx，全栈 `docker compose` 一键启动。

## 启动

```bash
./start.sh              # 等价于 docker compose up -d --build
```

| 入口 | 地址 |
| --- | --- |
| 前端页面 | http://127.0.0.1:8217/ |
| 后端接口 | http://127.0.0.1:8317/api/ |
| MySQL | 127.0.0.1:3517（库 `archive_center`） |
| Redis | 127.0.0.1:6517 |

## 停止

```bash
docker compose down       # 保留数据卷
docker compose down -v    # 连数据卷一起删，下次启动重新灌种子数据
```

## 业务模块

### 1. 库房与卷宗（`room`）

库房编号 `R-xx` 全库唯一，每间记「能放多少卷」，状态分 `在用 / 整理 / 停用`。
每间库房还有自己的**温湿度保管区间**（温度、湿度上下限，默认 14–24℃ · 45–60%，可在库房详情里调），
抄表越不越限、封不封库都按本库这套区间判。
页面是一棵**树**：库房为父节点、里面装的卷宗为子节点，点任一个右边出详情直接改；
封库中的库房挂红签「封库中」，详情里对账列出**现放（在库）· 外借未还 · 在册**三个数。

写入时校验：库房容量要大于 0；**容量不能改到比现在实际放着的卷数小**；
**库房里还有卷时不许改成「整理」或「停用」**（要先清空）；
温度/湿度下限要低于上限，湿度区间落在 0–100。
**封库状态只能由抄表驱动**：库房接口根本不看 `sealed` 字段，
改状态、改区间都解不了封，只有下一班抄表回到区间内才回温。

- 页面：库房与卷宗（`/rooms`）
- 接口：`GET /api/rooms`、`POST /api/rooms`、`PUT /api/rooms/{id}`

### 2. 案卷目录（`archive`）

卷宗号 `D-xxxx-xxx` 全库唯一，记题名、归档年度、保管期限（年）、所在库房，
状态分 `在库 / 已借出 / 已销毁`。页面按**归档年度分页签**浏览。

写入时校验：**只能往「在用」的库房放卷**；**放进去不能超出这间库房的容量**；
**已销毁的卷不能再改**；**还在外面调阅的卷不能挪库房**。
**目录里不能直接把状态改成「已销毁」、会签未结案期间也不能改保管期限**——
到期卷的销毁与续存一律走「到期鉴定台」会签。

- 页面：案卷目录（`/archives`）
- 接口：`GET /api/archives`、`POST /api/archives`、`PUT /api/archives/{id}`

### 3. 到期鉴定台（`appraisal`）

到期口径：**归档年度 + 保管期限年数 ≤ 今年**。落到当年及以前、没有销毁的卷都进待鉴定名单
（在库、借出在外都进；已销毁的卷不再进台）。

到期卷先**开鉴定单**再过**两人会签**：

- **一张卷同一时间只能有一条未结案鉴定单**：开单先锁案卷行，两人几乎同时开单时后到的失败并提示「已经在鉴定中」；库内另有生成列唯一索引兜底。
- 会签必须写**鉴定意见**（只许 `续存 / 销毁`）、**鉴定人**、**分管领导**，两个名字不得相同。
- 调阅中的卷可以出现在名单、可以开单，但**销毁结论提交不了，必须等归还**。
- 会签没齐之前：目录不能把这卷改成已销毁、不能改保管期限，库房现放卷数也不提前腾。
- 会签齐且结论**销毁**：卷宗变 `已销毁`，**所在库房当天就少一卷**，这卷不能再被调阅，也从到期台消失。
- 会签齐且结论**续存**：必须写续存年数，保管期限按年数加上去，卷宗保持在库，到期台这条消失。
- 会签进行到一半若有人绕过页面直接在库里把状态改成已销毁、或改掉保管期限，**提交失败、单子保持未结案**，并提示目录侧已经动过。
- 续存提交时若这卷刚被借走，续存失败、保管期限维持原值。

- 页面：到期鉴定台（`/appraisals`），含待鉴定名单、各库房现放卷数对账、鉴定单台账（未结案/已续存/已销毁）
- 接口：`GET /api/appraisals/pending`、`GET /api/appraisals`、`POST /api/appraisals?archiveId=`、`POST /api/appraisals/{id}/submit`

### 4. 调阅登记（`retrieval`）

一条调阅 = 某人在某天把某卷借走，约定应还日期。状态 `调阅中 → 已归还`。

写入时校验：**已销毁或不在库的卷借不了**；**同一卷同时只能有一条未归还的调阅**；
应还日期必须晚于调阅日期。登记时卷宗自动转 `已借出`，归还时自动转回 `在库`。
页面是**左右穿梭框**：左边「库里可借的卷」、右边「借出在外」，中间两个箭头借出/收回，
逾期的条目在右边标红并显示超了几天。

**封库联动**：所在库房封库中时，该库**新调阅一律开不成**——服务端直接拒，
单子落不成 `调阅中`、卷宗状态不动、现放卷数不减，页面上留下失败说明；
**已借出的卷归还照常收下**，卷当天回 `在库`，现放卷数当天加回。
封库中的卷在左边列表挂红签「封库中」，回温（见库房温湿度）后新调阅自动恢复，
回温前借出未还的卷继续算外借，不会当成已经回来。

- 页面：调阅登记（`/retrievals`）
- 接口：`GET /api/retrievals`、`POST /api/retrievals`、`POST /api/retrievals/{id}/giveback?returnDate=`

### 5. 库房温湿度（`room_check`）

每间库房每天量一次温度与湿度，记检查人。
**结论由服务端按本库上下限判**：温度或湿度任一边越出本库保管区间自动记为「异常」，
异常时**必须写清情况说明**，否则拒绝。**同一间库房同一天只能登记一条**，停用的库房不用检查。
页面做成**久未检查排行**：按「距上次检查天数」从多到少排，前两名标红，点「记录」当场补一次。

**封库口径**（`room.sealed`，只能由抄表驱动）：

- **连续两班最新抄表都越本库上下限，该库进入封库；只越一班只预警，不封**（页面上挂「越限预警」）。
- 封库期间：该库**新调阅开不成**（调阅台硬开会被拦下并留下失败说明）；
  **已借出的卷归还仍收下**，现放卷数当天加回；
  **温湿度页照常补本班抄表**，封库不把抄表口堵死。
- **回温 = 下一班（最新一班）抄表回到本库区间**，封库随即解除，该库新调阅才能再开。
- **回温前把历史班次补录/改成区间内的数，封库不解除**——封库状态只看最新一班抄表，
  历史班次动不了它；库房接口、案卷目录也都改不动 `sealed`。
- 刷新之后，各库现放卷数、是否仍封、已外借未还清单互相对得上。

- 页面：库房温湿度（`/checks`）
- 接口：`GET /api/checks`、`POST /api/checks`

## 目录

```
backend/src/main/java/com/archive/center/
├── config/       CORS 配置
├── controller/   REST 入口
├── dto/          BizException + 统一错误响应
├── entity/       5 张业务表
├── repository/   Spring Data JPA
└── service/      业务规则（容量校验、库房状态、唯一性、借还联动、到期鉴定会签、温湿度判定）

backend/src/test/                       H2 集成测试：鉴定流程规则 + 封库口径规则 + HTTP 全链路
frontend/src/views/                     5  个业务页面
```
